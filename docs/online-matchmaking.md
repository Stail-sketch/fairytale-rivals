# ランクマッチ・フリーマッチとプレイヤー名

## 遊び方

タイトルで名前を保存し、ランクマッチまたはフリーマッチを選び、語り手・使用デッキを選択して「対戦相手を探す」を押す。双方が同じ形式を選ぶと自動的に対戦を始める。CPUによる人数の補充は行わない。

ランク戦は1000 RPで開始する。近いレートの相手を優先し、待機時間とともに許容差を広げる。Elo方式（K=32）でサーバーが更新する。同レート同士の勝敗は±16 RP。ブロンズは1100未満、シルバーは1250未満、ゴールドは1450未満、プラチナは1700未満、それ以上はレジェンド。シーズンリセット・ランキング一覧・報酬はこの実装には含まない。

フリー戦はランク戦とは別の待機列で、RP・ランク戦績は変化しない。

検索はキャンセルできる。ただし、キャンセルと同時に相手が決まった場合は対戦へ移り、相手を放置しない。45秒間更新のない待機登録は失効する。再読み込みで検索または対戦を復元する。

手札交換と各ターンの操作時間は90秒。ターン・選択権・フェーズの切り替わりで制限を更新する。通信が切れても即座には敗北せず、残り時間内に再接続できる。制限を超えた操作担当プレイヤーは敗北。タイトルへの退出は投了として扱う。

## 名前・データ保存

- 名前は1～20 Unicode文字、前後空白除去、NFC正規化。制御文字・不可視の書式制御文字は拒否する。同名は許可し、表示名を認証や識別には使わない。
- パスワードを入力させず、サーバーが生成するランダムなIDと256bitの認証トークンで本人を識別する。サーバーはトークンのSHA-256ハッシュを保存する。クライアントは新規キー `fairytale-player-v1` に専用認証情報と表示用プロフィールを保存する。
- 名前変更は同じプレイヤーIDへの更新。既存デッキのキー・内容・名前・作成順には触れない。デッキのクラウド同期も行わない。異なる公開URL・ブラウザー・PC間でデータは自動共有されない。
- ブラウザーデータを消すと認証情報を失う。現時点ではアカウント連携・パスワード復旧・別端末ログインはない。認証情報をURLや共有デッキに含めない。
- 名前は通常のCPU戦、Cloudflareのフレンドロビー・フレンド対戦、ランク・フリーで表示する。旧PeerJS経由のフレンド対戦は従来の表示を維持する。

## サーバー実装

`cloudflare/matchmaking.js` の Matchmaking Durable Objectを一つの調整役とし、プロフィール・待機列・組合せ・勝敗確定を直列処理する。`wrangler.jsonc` のv2マイグレーションで新しいクラスを追加し、既存BattleRoomを削除しない。Pagesは引き続き既存WorkerへAPIを中継する。

API:

- `POST /api/players`：名前を登録して本人の認証情報を一度返す。IPごとの登録回数制限あり。
- `GET /api/players/me` / `POST /api/players/me`：認証付きの取得・名前変更。
- `GET /api/matchmaking`：検索更新・検索復元・対戦復元。
- `POST /api/matchmaking`：検証済み構築デッキで検索開始。
- `DELETE /api/matchmaking`：検索キャンセル。
- 以降の対戦は既存の認証付き `/api/rooms/:id` を使用する。

自分自身との組合せ、同一IDでの重複待機、ランクとフリーの混在を防ぐ。対戦相手には相手の認証トークンや非公開手札を返さない。クライアント申告の勝敗・レートを受け付けず、BattleRoomの確定結果から内部APIで更新する。結果は試合IDで一度だけ反映する。部屋作成の途中失敗は保存済み割当から復元し、勝敗保存の通信失敗はDurable Objectのアラームで再試行する。

ローカル開発は `development-worker.js` のメモリーアダプターで本番と同じハンドラーを動かす。開発サーバー再起動時のデータは消える。本番データはDurable Objectストレージに保存する。

## 検証

`tests/matchmaking.test.js`：既存デッキ保持、名前変更、同名プレイヤー、形式別待機列、自己対戦防止、検索キャンセル・期限切れ、不正認証・未知カード・内部API遮断、通常決着・投了・時間切れ、再接続、再起動、保存失敗・再試行での二重加算防止、フレンドの名前表示。

`tests/matchmaking.e2e.js`：独立した2ブラウザーで名前保存、既存デッキ保持、検索・マッチング、再読み込み、手札交換、名前表示、投了、双方のRP、フリー検索キャンセルを確認する。`FAIRYTALE_SERVER_URL` で公開先でも同じ試験を実行できる。
