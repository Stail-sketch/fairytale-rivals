# 童話戦記 · 第3弾まで収録した対戦試遊版

PCブラウザで遊べる横型カードバトル。タイトルから「CPU対戦」「同じPCで2人」「フレンド対戦」を選べます。

**公開版：[Cloudflare版の童話戦記](https://fairytale-rivals.pages.dev/)**

開発ソースは引き続き [Stail-sketch/fairytale-rivals](https://github.com/Stail-sketch/fairytale-rivals) で管理します。

## プレイ

プロジェクトフォルダで Node.js 22 以上を使用します。依存パッケージのインストールは不要です。

```powershell
npm start
```

[対戦画面を開く](http://127.0.0.1:4173/)。CPU対戦では自分とCPUの語り手を選び、自分の手札を確定すると対戦が始まります。CPUは手札交換と自分の手番を自動で操作します。手札をクリックして光るマスに召喚するか、ドラッグで配置します。攻撃可能なユニットもクリックまたはドラッグで対象を選べます。対戦終了後に、シードと操作履歴を含むJSONを保存できます。

タイトルの「デッキ編集」で保存済みのデッキを9件ずつ見られます。「新規作成」でクラスを選び、デッキ名を入力して編成します。候補カードとデッキ内のカードにはイラスト、名前、効果が表示されます。共通カードと選んだクラスのカードを組み合わせて30枚にすると保存できます。同名カードは2枚まで、レジェンドは1枚までです。同じクラスのデッキも複数保存できます。以前に保存したデッキは同じブラウザーの一覧へ引き継がれます。

デッキ一覧と編成画面の「全体表示」では、カードを1枚ずつ並べて確認できます。カードを選ぶと効果を表示し、下にMP別の枚数とユニット・特技・武器の内訳を表示します。

デッキ一覧は戦士、魔法使い、武闘家、僧侶、商人、占い師、魔剣士の順に並びます。同じクラスでは作成順です。各デッキの「削除」ボタンから個別に削除できます。

URLを移行すると、ブラウザー内のデッキは自動では共有されません。旧GitHub Pages版の「デッキ編集」→「デッキを書き出す」でJSONファイルを保存し、Cloudflare版の「デッキ編集」→「デッキを引き継ぐ」で読み込んでください。名前・カード・作成順を保持し、既存デッキは上書きしません。同じ名前・同じ内容のデッキは重複して追加しません。別のPC・ブラウザーへの引き継ぎにも使えます。

カードライブラリとデッキ編集では、童話戦記のカード名、原作のカード名、効果で検索できます。「メラミ」で「夢時計の弾丸」が見つかります。レアリティと収録弾の絞り込みも併用できます。

「デッキ編集」→「スクショから作成」で、ドラゴンクエストライバルズのデッキ詳細画像を貼り付け、ドロップ、またはファイル選択できます。カードの絵柄をブラウザーで照合し、1枠を1枚として数えます。確認画面で原作名と童話戦記の対応カードを見比べ、読み取れなかった枠や修正したい枠はカード名で検索できます。クラスとデッキ名を確認し、「デッキ編成へ」から通常どおり保存します。

照合対象はベーシックから第3弾までの原作対応573種です。画面全体に動画の操作表示などがある場合も、カードの枠がすべて見える画像を使います。

全7職業の初期デッキ9件が、最初にデッキ一覧に入ります。各ブラウザーで編集や削除ができ、すでに同名・同内容で保存済みのものはそのデッキを使います。

対戦前に、選んだ語り手の保存済みデッキを名前で切り替えられます。CPUは第3弾のカードを組み込んだ職業別デッキを使います。

「カードライブラリ」には原作対応のデッキ用カード573種、検証用30種、対戦中に生成される45種があります。原作対応のデッキ用カードはベーシック86種、第1弾287種、第2弾100種、第3弾100種です。全648種に別々のイラストがあります。「語り手の奥義」タブでは7人の効果を確認できます。対戦中は熱量が3になると奥義を使用できます。装備した武器、またはリーダーの攻撃力を上げる効果がある場合、自分の肖像からリーダー攻撃を選べます。

同梱の `play.html` は同一のソースから生成した依存ファイル不要の試遊版です。ブラウザで直接開けます。

対戦画面は左右対面式です。操作中の語り手は左、相手は右に位置し、中央で双方の前衛が向かい合います。前衛と後衛の同列マスは水平に揃っています。

第3弾のカードで配置される「物語の舞台」は、盤面のマスに名前が表示されます。効果はマスにカーソルを置くと確認できます。「六彩の暁鳥」から生まれる6色の種晶を自分の盤面に並べると、特殊勝利になります。

手札や盤面のカードにカーソルを合わせると、イラスト、効果全文、キーワードの説明、現在の状態が詳細欄に出ます。広い画面では右側に表示し、戦場は中央に配置します。

カードライブラリ・デッキ編集・対戦で、カードが生成・召喚する関連カードを確認できます。効果文の青い用語を押すと説明が開きます。相手の奥義は肖像の下で確認でき、未来視や未来の統合の状態はリーダーの近くに表示します。

攻撃するユニットを選び、相手にカーソルを置くと、戦闘で与えるダメージと反撃後のHPが表示されます。前衛などが攻撃を阻んでいる場合は、守っているユニットが光ります。手札・盤面のカードは長押し、右クリック、またはフォーカス中に `I` キーで詳細を開けます。

カードの使用、攻撃、地形の発動は、盤面の発動元から対象へ動きます。「対戦記録」から発動元・対象とカードの詳細を確認できます。決着画面には最後の一手が表示されます。「短い演出」と「効果音」の設定はブラウザに保存されます。

対戦BGM「月下の綴り」は、いずれかの語り手のHPが8以下になると、同じ曲の拍に合わせて打楽器が加わります。対戦結果に応じて短い曲が流れます。右上の「音量」から、BGMと効果音を個別に調整できます。

## 物語の闘技場

タイトルの「物語の闘技場」から、CPU勝ち抜きかフレンド闘技場を選べます。各自にランダムな3人の語り手が提示され、1人を選びます。異なる3つの扉から1つを選び、3枚の候補から1枚ずつ5回ピックします。扉選択を6回行って30枚にします。クリックで候補を選び、確認ボタンで確定します。

扉は「語り手」「仲間」「魔法」「小さな冒険」「大いなる物語」「めぐり逢い」の6種類。専用カード、ユニット、特技・武器、0〜3MP、5MP以上、共通カードの抽選重みをそれぞれ3倍にします。出現対象はベーシック〜第3弾の573種類で、他クラス専用・生成カード・検証用カードは出ません。同じ3択内は重複せず、取得後に再び候補になることはあります。闘技場ではレジェンドを含め同名枚数の制限がありません。通常のデッキ編集は従来の制限を維持します。

配分はノーマル12〜17枚、レア8〜12枚、スーパーレア3〜5枚、レジェンド1〜3枚の範囲で、合計30枚になる組み合わせを抽選します。1回の3択は同じレアリティです。フレンド版では同じロビーの二人で配分・レアリティの出る順序を共有し、クラス候補・扉・カード候補は別々に抽選します。相手には進捗だけを表示し、候補やデッキは送信しません。サーバーがピックを処理し、完成したデッキでのみ準備OKにできます。

CPU版は1敗するまで同じデッキで連戦し、引き分けでは勝利数を変えず続行できます。CPUも同じレアリティ配分で闘技場デッキを生成します。勝利後の相手はMP配分とユニット数を考慮してカードを選び、カード性能は変更しません。ピック途中と各対戦操作後にブラウザーへ保存し、「一時保存して戻る」「保存して中断」から再開できます。勝利数と最高記録も同じブラウザーに保存します。

フレンド版はロビーID・招待URLで合流し、各自でピックして準備OKにします。対戦後は同じデッキで再戦でき、ロビーへ戻ってホストが「二人のピックを作り直す」を選ぶと、配分から抽選し直します。Cloudflare版はピックの進捗もサーバーに永続保存します。参加権限は同じURL・同じタブ内の情報を使います。

## フレンド対戦

[Cloudflare版](https://fairytale-rivals.pages.dev/)では、ロビーと対戦状態をDurable Objectsに保存します。タブの再読み込みやサーバーの再配置後も、期限内なら同じURL・同じタブから対戦に戻れます。相手の手札はサーバーで伏せ、各自が自分のブラウザーに保存したデッキを選びます。

[旧GitHub Pages版](https://stail-sketch.github.io/fairytale-rivals/)はデッキの書き出し用にも残します。旧版のフレンド対戦はWebRTC方式のため、ホストがタブを閉じたり再読み込みすると部屋が終了します。新しく遊ぶ場合は双方でCloudflare版を使ってください。旧版のロビーID・招待URLはCloudflare版へは移りません。

1. 「フレンド対戦」で「ロビーを作る」を押し、表示される8文字のロビーIDを友達に伝えます。
2. 友達はゲームを開き、「ロビーIDで参加」からIDを入力します。「URLをコピー」で送った招待URLからも参加できます。
3. ロビーに合流してから各自でデッキを選び、「準備OK」を押します。二人とも準備ができたらホストが「対戦開始」を押します。
4. 対戦結果で双方が「再戦」を押すと、同じデッキで次の試合が始まります。「ロビーに戻る」を押すと両者が同じ部屋でデッキを選び直せます。ロビーIDと招待URLは次の試合にも使えます。
5. 対戦中に「タイトル」から退出すると相手の勝利になります。Cloudflare版とNode.jsサーバー版では、タブを閉じただけの場合も部屋の状態を保持します。再読み込み用の情報は同じタブ内に保存されます。閉じたタブを復元できない場合は、参加権限の情報がないため同じ参加者としては戻れません。

`127.0.0.1` の招待URLは同じPC内で試遊できます。別の回線の友達と対戦する場合は、双方がアクセスできるHTTPS環境でこのNode.jsサーバーを起動し、そのHTTPS URLから部屋を作ります。サーバーは `PORT` または `FAIRYTALE_PORT` で待受ポートを指定できます。`PORT` が設定されている場合は全インターフェースで待ち受けます。`FAIRYTALE_HOST` で待受アドレスを変更できます。

Cloudflare版では、参加待ち・終了済みの部屋は30分、進行中の部屋は2時間操作・接続がないと期限切れになります。接続中は期限を延長し、期限切れの保存データはアラームで削除します。Node.js版の部屋はメモリ保存なので、サーバー再起動で消えます。`play.html` はCPU対戦と同じPCでの対戦を試せます。

## Cloudflareへの公開

Node.js 22以上で次を実行します。認証情報はリポジトリに保存しません。

```powershell
npm ci
npx wrangler login
npm run dev:cloudflare
```

ローカルの [Cloudflare実行環境](http://127.0.0.1:8787/) で確認したら、`npm run deploy:cloudflare` で公開します。このコマンドは対戦サーバーのWorkersと、短い公開URLのPagesを両方更新します。`wrangler.jsonc` にWorkersとSQLite対応Durable Object、`cloudflare/pages/wrangler.jsonc` にPagesから対戦サーバーへのサービス接続を設定しています。配信ファイルは `dist` と `dist-pages` に生成し、開発資料・テスト・認証情報は含めません。GitHubへpushしただけではCloudflareの公開版は更新されないため、変更後はこの公開コマンドも実行します。

公開URLは `https://fairytale-rivals.pages.dev/` です。以前のWorkers URLもデッキの書き出し用に残します。Workers URLで保存したデッキはその画面の「デッキを書き出す」から保存し、新しいPages URLの「デッキを引き継ぐ」で読み込んでください。対戦APIは内部のサービス接続で同じサーバーへ届きます。既存のロビーIDも同じサーバーで扱いますが、参加権限は元のURL・同じタブに保存されるため、進行中の試合は元のタブで続けてください。

対戦APIの検証先は `FAIRYTALE_SERVER_URL` で切り替えられます。

```powershell
$env:FAIRYTALE_SERVER_URL='http://127.0.0.1:8787'
node --test tests/online.e2e.js
node --test --test-name-pattern='別々のChromium' tests/browser.e2e.js
```

## テスト

```powershell
npm test
npm run test:e2e
npm run build
```

E2Eは Chrome または Edge を使用します。インストール先が異なる場合は `FAIRYTALE_BROWSER` に実行ファイルのパスを設定します。フレンド対戦のE2Eはテスト用にローカルHTTPサーバーを起動します。ビルドはソースから単体の `play.html` を再生成します。

## 構成

- `packages/engine` にエンジン、ルール定数、コマンドと効果のTypeScript型宣言。
- `packages/cards` にカード定義、語り手と正式用語。
- `packages/local-match` に対戦コマンド窓口とプレイヤー別の状態表示。
- `packages/online-match` に招待部屋、操作の受け付け、プレイヤー別の状態配信。
- `packages/cpu` に、CPUの見える情報から合法手を試算する対戦AI。
- `apps/web` に操作画面と新規アート素材。
- `cloudflare` に公開用Workerと、ロビー・対戦を永続保存するDurable Object。
- `docs` に[マスター仕様](docs/master-spec-v1.0.md)、[原作カード一対一対応表](docs/card-correspondence.md)、[ロードマップ](docs/roadmap.md)、[裁定と出典](docs/rulings.md)、[素材の生成記録](docs/art.md)。
- [マスター仕様の追補](docs/master-spec-addendum-card-mapping.md) に職業専用・共通カードの原作対応方針。
- [語り手の奥義と参照先](docs/leader-skills.md) に奥義と生成カードの効果、原作で確認が残る裁定。

カード追加時は、生成・召喚などの効果に対象カードのIDを設定し、効果文に正式用語を使います。各画面が効果データから関連カードを表示し、共通の用語集から説明を表示します。新しい効果の参照先や新しい用語は [関連カードの表示](apps/web/card-related.js) と [用語集](apps/web/card-terms.js) に登録します。

Node.jsの標準ライブラリとブラウザ標準機能で実装しました。CPU対戦と同じPCでの対戦は画面更新で終了します。第1弾の採用範囲、資料間で値が異なるカード、原作で確認できていない処理順は[対応表](docs/card-correspondence.md)と[裁定ノート](docs/rulings.md)に記録しています。
